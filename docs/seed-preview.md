# 种子预览（Seed Preview）

> 给一个版本 + 种子，出一张「这个世界长什么样」的粗图：生物群系色块、史莱姆区块、
> 结构起点。图由**面板自己缓存的那个 `server.jar`** 生成，不是另写一套地形算法。

## 1. 是什么

- 在 MC 实例页的「种子预览」页签里：填种子 → 起一次预览 → 得到一张 PNG 和一份结构清单。
- 版本默认取当前实例的版本，可以改。范围 512 / 1024 / 2048 格三档。
- 结果按 `(版本, 种子, 半径, 采样高度, 渲染代数)` 缓存，同样的请求第二次是瞬时的。

## 2. 不是什么

- **不是实时地图**。它要起服务端、生成区块，秒级到分钟级，是一次显式操作。
- **不是 3D 渲染**。没有视角、没有光影贴图；是俯视的平面图，用高度做明暗。
- **不是世界生成器**。它不参与正式开服，生成的世界在出图后立即删除。
- **不替代 `/i/*` 反代**。游戏协议是二进制 TCP，和 HTTP/WebSocket 无关，两件事。

## 3. 为什么用真服务端

1.18 之后的地形是 density function + 多噪声生物群系，重写一套等价实现的工作量以人年计，
而且每个大版本都要重来。用真 jar 的收益是**永远不会和游戏本身产生偏差**：

- 正确性跟随版本：下载哪个版本的服务端，出的就是哪个版本的地形；
- 面板不碰游戏逻辑：协议、结构、群系全归 Mojang，面板只读文件；
- 版本矩阵不是代码问题：1.12.2 和 1.21 的差异在**解析层**，不在算法层。

代价是慢。这是有意的取舍：预览是低频操作，慢几秒换「不会错」。

## 4. 一次预览会发生什么

```
校验参数
→ 找 jar（已缓存直接复用，否则下载一次并校验 SHA-1）
→ 找 Java（按版本要求；1.16.5 需要 Java 8/11，1.21 需要 21）
→ 临时目录 + eula.txt + server.properties（level-seed / online-mode=false / view-distance=2）
→ 起 java -jar server.jar --nogui，等 stdout 出现 `Done (`
→ 请求生成：1.14+ 用 /forceload（每批 256 区块），更早的版本用 /setblock 逐区块促载
→ 轮询 region 文件的头部位图，数落盘区块
→ save-all flush → stop → 等进程退出
→ 解析 region（生物群系 + 结构起点）→ 出 PNG
→ 删除临时世界，保留 preview.png 与 meta.json
```

进度只有一个诚实的信号：**region 文件头部的区块位图**。命令返回不代表区块已生成，
所以不用 sleep 判断完成。

## 5. 三个版本族的区块布局

| 版本 | 生物群系 | 结构 |
|---|---|---|
| ≤ 1.12.2 | `Level.Biomes` `byte[256]`，一格一块 | `Level.Structures.Starts`，键名首字母大写（`Village`） |
| 1.13 – 1.17 | `Level.Biomes` `int[1024]`，4×4×64 | 同上 |
| 1.18+ / 1.21 | `sections[].biomes` 调色板（4×4×4） | `structures.starts`，键名是资源位置 |

判断依据是**数组长度和 tag 类型**，不是版本号：预发布版和 datapack 会移动边界。

平面图在 `biomeY`（默认 63）取切片；1.15 之后群系是三维的，同一张图在不同高度会不一样，
这是产品选择，不是技术限制。

## 6. 图上有什么

- **1 像素 = 1 格**。生物群系只有 4 格粒度，但高度图是逐格的——地形是否看得出来，
  靠的是高度，不是群系。
- **按地表方块上色**：草方块取群系绿、沙/沙岩取沙色、石/深板岩取灰、雪与冰取白、
  树叶取更深的群系绿。地图模组看起来干净，是因为它画的是材料而不是高度。
- **明暗**：从西北打光，高度先做两轮 6 格箱式模糊，去掉树冠噪声只留下地形起伏。
- **海岸线**：陆地紧邻水的一格压暗，让大陆有轮廓。
- **水**：按海底深度从浅蓝到深蓝。
- **网格**：64 格一格，256 格加粗；红白十字是 (0,0)。
- **史莱姆区块**：半透明绿；**结构**：菱形标记，按家族分色。
- 坐标在页面上悬停读取（图像本身不烧字，缩放不会糊）。
- **缩放与拖动**：滚轮以光标为中心缩放（1×–12×），拖动平移，双击复位。
- **图层开关**：网格 / 史莱姆 / 结构三个开关。这三层是浏览器里的 SVG，不是烧进
  PNG 的——PNG 只有地形（那是要跑世界生成的），开关切换是瞬时的。

## 7. 资源与上限

| 项 | 值 |
|---|---|
| 半径 | 64 – 1024 格（最多 128×128 = 16384 区块） |
| 并发 | **全局 1**。生成是面板最重的操作，两个并发会让所有页面变慢 |
| 内存 | 预览服务端 `-Xmx1G` |
| 磁盘 | 临时世界出图即删；图片缓存上限 256MB，超出按最旧淘汰 |
| 超时 | 启动 3 分钟、生成 6 分钟；生成超时仍出图，标记 `partial` |

预览进程固定带 `-XX:-UseBASE64Intrinsics`（Java4Shell 的兜底，见 README 的安全说明）。

## 8. API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/mc/preview/capabilities?version=` | jar 是否已缓存、需要哪个 Java、是否就绪（不触网） |
| POST | `/api/mc/preview` | `{version, seed, radius, biomeY?}` → 202 作业 |
| GET | `/api/mc/preview/{id}` | 状态、进度、日志尾部 |
| GET | `/api/mc/preview/{id}.png` | 地图 |
| GET | `/api/mc/preview/{id}.json` | 结构清单与统计 |
| DELETE | `/api/mc/preview/{id}` | 取消（会杀掉预览服务端） |

挂在 `/api/mc/*` 之下，所以同时受 MC 功能开关与会话登录门保护。

## 9. 失败与降级

| 情况 | 表现 |
|---|---|
| 版本 jar 缺失 | 首次预览时下载；失败则保留错误，不排队 |
| Java 未安装 | 明确提示需要哪个大版本，并指向「Java 运行时」 |
| 启动超时 | 失败，附服务端最后几行输出 |
| 生成超时 | **出图**并标 `partial`，不报失败 |
| 进程崩溃 | 失败，附日志尾部；临时目录清理 |

## 10. 版权与红线

- jar **运行时下载、只在用户自己的数据卷里**，面板不打包、不随镜像分发。
- 生成出来的世界属于用户自己的实例，出图后删除，不进入任何发布物。
- 预览只服务「面板自己管的服务器」，没有「填一个别人的服务器地址」的入口——
这条边界也是这个功能与「第三方客户端」的分界。
