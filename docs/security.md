# 安全说明

> 这一页写给**要把它暴露到网络上、或者让它跑别人的 agent 的人**。
> 一句话：**面板的作用是把 agent 关进你选的笼子里；它不负责把笼子造好。**

其它文档各讲一面：`design-notes.md §7` 记「为什么这样设计」，`web-shell.md §4` 是终端那条
攻击面，`deployment.md` 讲怎么装。这一页只讲三件事：**你可能被谁害、面板挡住了什么、
你自己怎么把它搞砸。**

---

## 0. 先花一分钟回答三个问题

1. **谁可能碰到这个端口？** 公网扫描器 / 同内网的其他人 / 只有你自己。
2. **谁可能在面板里跑代码？** 你自己 / 你信任的同事 / 不受信的 agent 与用户提供的文件。
3. **这台机器上还有什么值钱的东西？** 别人的数据、生产环境的 key、内网里能横向访问的服务。

这三个答案决定后面每一条的权重。**答不出第 3 题的人，通常会把它配成公网可访问的样子。**

---

## 1. 威胁：按可能性排

| 威胁 | 谁 | 面板能挡吗 | 你要做什么 |
|---|---|---|---|
| 公网扫描、撞库 | 互联网上的任何人 | **能挡大半**：登录门 + 失败预算 + HTTPS | 别裸 HTTP 暴露；前面加反代/VPN/白名单 |
| 被投毒的 agent | 模型自己、它拉下来的包、`curl \| sh`、提示注入 | **挡一部分**：容器里 agent 降权、秘密文件 0700 | 别把生产 key 配进来；容器部署 |
| 同一台机器上的其他账户 | 多用户主机、裸部署 | **挡不住**：0600 只在有 uid 分离时才有意义 | 裸部署按单用户机器对待 |
| 会话 Cookie 被偷 | 共享设备、XSS、日志泄漏 | **挡得住一部分**：HttpOnly + SameSite + HTTPS + 提权 | 别在不可信设备登录 |
| 面板自身的漏洞 | 任何人 | **挡不住**：面板被攻破 = 它能做的事全丢 | 只信你审过的版本；最小暴露 |
| 宿主管理员 / 容器逃逸 | 有宿主权限的人 | **挡不住**，这是上限 | 宿主本身要可信 |
| 你自己的误操作 | 你 | **挡一部分**：备份、E-Stop、审计 | 先备份再点 |

**这张表的读法**：面板把自己的边界守得挺紧，但边界之外的东西（网络、宿主、agent 的可信度、
key 的价值）全是部署者的责任。

## 2. 面板实际做了什么（可以逐条核对）

### 2.1 进门这一层

- **口令存储**：PBKDF2WithHmacSHA256，per-user 盐，21 万次迭代；文件原子写入并收紧到 0600。
- **失败预算**：同一来源地址 5 分钟内错 15 次，第 16 次起拒绝 10 分钟（响应带 `Retry-After`），
  期间**口令正确也进不来**；一次成功清零。拒绝发生在**核对口令之前**——核对本身
  （21 万次 PBKDF2）就是攻击者想让你付的那笔开销。
- **来源地址取 TCP 对端**，不信 `X-Forwarded-For`。所以面板架在反代后面时，这个预算是
  **所有访问者共用**的（这是有意的：伪造头部换 IP 成本太低）。
- **会话**：默认 168 小时（`sessionTtlHours`），Cookie 是 `HttpOnly` + `SameSite=Strict`，
  HTTPS 下加 `Secure`。改密码或改用户名会立刻踢掉该用户的其它会话。
- **`auth.disabled: true` 只在绑定回环地址时允许**——免登录可以，误配到公网不行。

### 2.2 第二把锁：开发者模式

它守的是"能执行代码"那一类动作：实例终端、E-Stop、开发者守卫档位、装包等。

- **HTTPS 是完整体；HTTP 下开发者密码只当第二道验证。** 在裸 HTTP 下仍可设置/修改
  开发者密码并提权，用它把 `/api/*` 和 `/i/*` 挡住（**已设置开发者密码时**，
  远程明文的 `developer_guard.scope` 会被强制提升到 `ALL`；还没设密码时不强制——
  否则设置、证书、Node 全被一把还不存在的密码锁住，新部署无法配置）；
  但 **Web Shell、实例终端、agent 密码、guard/终端相关设置仍然只在 HTTPS 下可用**。
  裸 HTTP 下终端按钮隐藏、对应接口 403；不要把它当成完整开发者模式。
- **口令存在独立的 `auth/developer.json`（0600）**，与登录口令分开：偷到登录态不等于能开终端。
- **提权是会话级的**：默认 30 分钟滑动（`DeveloperElevation.TTL`，可一次延长到 3 小时）；
  10 分钟内错 3 次，这个「会话 + 地址」就被锁 10 分钟。
- 提权的 key 绑定「会话 + 来源地址」，换一个地址不算提权。

### 2.3 实例终端（效果上等于 RCE，所以门最多）

- 顺序固定：**E-Stop → Web Shell 总开关 → HTTPS → 开发者口令已设置 → 已提权**，五道全过才谈启动。
- 启动的是**适配器解析出来的 argv**，不经 shell：Windows 上 `.cmd` / `.bat` / `.ps1` / `.com`
  一律拒绝（`CreateProcess` 会悄悄把它们交给 `cmd.exe`，那等于塞回一个 shell）。
- 一个实例同时只有一个终端；重连发新 ticket 而不是重启 agent；关浏览器只是 detach。
- ticket 是一次性的：32 字节随机、30 秒过期、绑定「会话 + 实例」。
- 容器里面板是 root、终端进程降权到 uid 1000（见 §2.7）。
- **这五道门只管面板自己的终端。** 第三方品牌可能自带交互终端——PI WEB 的浏览器终端、
  ZCode 的网页终端（上游 3.14.3 起就有）都是；它们由各自产品鉴权，不受上面除 E-Stop 外的
  任何一道约束。面板的终端门只挂在 `POST /api/brands/{brand}/instances/{id}/terminal` 上，
  `/i/<id>/` 里的品牌终端不经过它。见 §2.4 与 [`brands.md`](brands.md) 的「PI WEB」、
  [`zcode-experimental.md`](zcode-experimental.md)。

### 2.4 反代与实例网页

- `/i/<id>/` 要会话；实例的访问 token 每进程随机、只存内存、重启即换。
- 反代只转发面板算出来的目标，请求里没有"我要连哪个端口"这种参数。
- **第三方工具自带的界面不是面板的门。** `/i/<id>/` 只是把请求转给实例；实例内部再有什么
  入口——品牌自带的终端（PI WEB 的浏览器终端、ZCode 的网页终端，以及以后任何带终端的品牌
  UI）、插件、agent 自己的工具——由那个产品决定。这些终端与 agent 同 uid，效果上等同于
  实例终端的 RCE 面，却只有各自的访问密码。面板的终端门只覆盖
  `POST /api/brands/{brand}/instances/{id}/terminal`，不覆盖 `/i/<id>/` 里的品牌终端。
  因此：不要把实例端口直接暴露，实例只经 `/i/<id>/` 访问；要门禁就把
  `developer_guard.scope` 设为 `proxy`（`/i/<id>/` 的 HTTP 与 WebSocket 都要求提权），
  别把面板终端门当容器围栏；agent uid 不应具备 sudo / docker 等价权限。

- **首次部署的提示不是安全控制。** 首页「部署检查」卡片和手机汉堡上的红点会标出「HTTP
  明文 + 非回环监听」「没设开发者密码」这类状态，但它只是提示：真正拦住未配置实例的是
  创建/安装前的 Node 预检（`409 node_missing`）和开发者守卫本身。卡片可以关掉，守卫不会
  因为卡片被关掉而失效。

### 2.5 紧急停机（E-Stop）

- 三次确认，第二次要手打「紧急停机」四个字；按下后先关所有终端，再杀所有实例的进程树，
  审计里记一笔。**不跑用户的 post-exit 脚本**——紧急停机不该再去执行用户代码。
- 状态只存在内存里：**重启面板或容器就解除**，这是唯一的物理恢复方式；冷却 1 小时内谁都不能解除。

### 2.6 审计

- 记谁、从哪个地址、做了什么（登录、终端开关、实例起停、装包、E-Stop、证书授权与撤销…），
  不记屏幕内容、不记 key。
- 文件 `<data>/logs/audit-*.jsonl`，0600；**保底保留 180 天**（低于这个数就答不上"上季度谁删了那个世界"）。

### 2.7 容器里的身份划分（v0.6.44 起）

- **面板是 root**，`auth/`（含开发者/agent 口令哈希与 ACME DNS/CA 凭据）、`certs/`
  （TLS 私钥，含 ACME 证书）、`logs/`（审计）、`server.yaml` 是 root `0700/0600`；
- **每个 agent 进程降权到 uid 1000**（`setpriv`，exec 原地替换，进程组与 PTY 会话不变）；
- 所以 agent **读不到也改不了**面板的凭据，也 `kill` 不掉面板、ptrace 不了它；
- **反方向的文件要交还**：pnpm 的 `~/.config/pnpm/config.yaml` 这类"面板写、agent 读"的配置
  不是秘密，写成 `root 0600` 会让 agent 的 `pnpm` 连读都读不了（两段身份的第一版就是这样，
  所有实例安装全挂 `EACCES`）。这类文件由 `Privileges.handToAgent()` 连属主带 mode 一起交给
  uid 1000；同一处还顺手拒了"agent 在自家目录里放个符号链接、面板以 root 顺着写"这条路。
- **裸部署没有这一层**：面板与 agent 同一个 uid，那些 0600 文件对 agent 是可读可写的。
  要隔离请用容器部署。
- **容器里改成非 root 运行，这一层同样不成立**：镜像设了 `USER`，或 compose 里写了
  `user:`，面板就不再是 root，`setpriv` 这步没有意义，所有子进程都跟面板同一个 uid。
  服务照常启动，所以面板在启动横幅里明说一句
  （`this container does not run the panel as root … the UID split … is NOT active`）——
  启动正常不等于隔离生效，去掉那个覆盖项才有。
### 2.8 有些环境里这一层不成立——**程序也无能为力**

不是每个文件系统都执行 mode 位。**ACL 管理的共享**（QNAP 的 trimacl 是典型；部分 NAS 的
SMB/NFS export、某些 Windows 共享卷同样如此）会把**共享属主**当成管理员放行：一个 uid 1000
的进程即使面对 `root:root 0700` 的目录，也照写不误。

这是**存储层的语义，不是面板的 bug，镜像里也没有办法绕过**：

- 它不归容器管。容器里的 uid 与宿主 1:1 映射，ACL 的判定发生在文件系统那一侧；
- `chmod` / `chown` 照样"成功"，`stat` 照样显示 `700`——只有真的去访问才暴露真相，所以
  光看 `ls -l` 会被骗；
- 因此面板启动时会**自检**：以 agent 身份试写一次 `auth/`。写得进去就打

  ```
  HDSL-web: WARNING: this filesystem does not enforce mode bits for uid 1000.
  HDSL-web: auth/, certs/ and logs/ are NOT protected from the agent on this host.
  ```

  这条日志是唯一可靠的信号。

确认不成立之后只有三条路：

1. **换存储**：`/data` 放到普通 ext4/xfs（loopback 镜像，或关掉共享的"高级文件夹权限"）；
2. **换 uid**：`--build-arg HDSL_AGENT_UID=1001` 重建镜像。共享属主通常是 1000，换一个不是
   属主的号就绕开了这条规则（宿主上挂给 MC / 工作区的目录也要跟着归新 uid）；
3. **接受**：把"这台机器上没有隔离"当成部署事实——**不要在安全评估里声称有**。入口那条
   WARNING 就是给这种情况留的：它诚实地告诉你，理论上的保护和实际发生的事不是一回事。

### 2.9 agent 凭证：agent 密码，不是第二把开发者密码

- **两串密码、两个文件**：`auth/developer.json`（人用，提权后做终端 / E-Stop / 装包）与
  `auth/agent.json`（agent 用，只能换票）。agent 密码**不是**提权的替代品：把它输进提权框
  只会得到「密码不正确」。
- **一条门**：`POST /api/developer/agent-auth`。免会话（curl 可用），但要求**此刻有人正在
  提权**；换出的票寿命被提权窗口截断，操作员登出或「停止提权」后票当场失效。
  **只在 `developer_guard.scope` 为 `instance` / `all` 时存在**：默认的 `off` 档下会话本身
  已经约等于全权限，这条门答 `409 agent_password_not_applicable`，面板上对应的按钮也不亮。
- **scope 十二类**：`read`（`/api/*` 的 GET，**不含聊天**）、`mc`（启停、单行指令、日志）、
  `mc-console`（MC 的 PTY 控制台 attach，单独一类）、`system`（宿主机 CPU/内存/磁盘/网络读数）、
  `instances`、`config`、`plugins`、`transcode`、`transcode-raw`、`chat-read`、`chat-write`、
  `chat-search`。默认只给 `read`；未分类路由一律拒绝；`/i/*`（反代）与 `/ws/*`（事件流）
  任何 scope 都不放行；凭据类路由（`admin-password`、`/open`、`/exports`、`/developer/*`、
  `/auth/*`）在网关拒绝。`chat-write` 的输入上限由聊天设置的 `agentChatMaxInputTokens`
  控制；`chat-search` 单独控制搜索成本。
- **自杀闸靠内核身份，不靠自报**：面板按平台原生接口推导**调用者住在哪个实例**——Linux
  走 `/proc`（socket inode → 持有进程 → ppid 链；容器里面板是 root、实例是 uid 1000，而
  默认的 root 没有 `CAP_SYS_PTRACE`、读不了 agent 的 fd 表，所以「inode → 持有进程」这一步
  交给一个 `setpriv` 到 agent uid 的子进程完成，面板自身不被授予该能力，见
  `SocketOwnerLookup`），Windows 走 `GetExtendedTcpTable` 的
  TCP owner 表（连接自带 pid）加 JDK 进程快照，两端都在命中实例根后用成员关系复核、挡
  PID 复用。三个家族（dsh / 品牌 / ZCode）的 stop / 删 / 开终端 / launch 都在闸上：推导出
  是自己 → `409 self_operation_refused`（正文写明原因）；推导不出时用票的绑定兜底；
  **既推导不出又未绑定的票，任何实例的致命操作一律拒绝**。藏在进程树外（`setsid`、系统
  代理、容器外）只会丢致命权限，不会被认成别人；偷来的票从别的进程发同样推导不出原主，
  致死力带不走。其余平台退化为「自报绑定 + 未绑定即拒」。
- **绑定在换票时推导**：`agent-auth` 那条连接被反查，住在哪个实例票就绑哪个（`family/id`）；
  推导不出才用调用者自报的 `instanceId`。**在实例里换票即自动绑对**，模型不用知道自己是谁。
- **人走的门不装自杀闸**：会话（含开发者提权）停掉跑着 agent 的实例是运维，面板照常执行、
  照常审计。这扇闸只分辨 agent。
- **操作员可以直签票**：`POST /api/developer/agent-token`（设置页「生成票并一键复制」）
  用提权会话签票，范围当场勾选、不受 agent 密码上限约束。这条门在 0.6.60 被撤过——当时
  挡自杀的只有票上的绑定，未绑定的签发票等于递枪；自杀闸改为按请求识别调用者后它才回来。
  agent 拿任何票都到不了 `/api/developer/*`，签不出自己的继任者。
- **审计**：agent 的调用记成 `agent:<label>`，并带机器判定的 `grant` / `scopes` / `caller`
  字段；网关拒绝（scope 与自杀闸）记 `agent.denied`（`self_refused` 等 outcome），护栏起
  作用与缺席都看得见；换票、吊销、停实例等都在 `audit-*.jsonl`。

### 2.10 证书、ACME 凭据与 SNI

- `/data/certs/registry.json`、`certs/<id>/privkey.pem`、`uploaded.*`、`self-signed*`
  都是 TLS 身份；`certs/` 归 root `0700`，注册表与私钥 `0600`。备份 `/data` 时按敏感数据对待。
- `/data/auth/acme.json`（0600 root）存 DNS provider token（Cloudflare API Token、阿里云
  AccessKey、DNSPod/腾讯云、GoDaddy、DigitalOcean、Vultr）和 CA 的 EAB 凭据；不进
  `server.yaml`，API 只回脱敏字段。**它等于域名控制权**：拿到 token 可以改 TXT、签发或
  吊销证书。按最小权限创建（只给 Zone.DNS 编辑一类权限）、单独专用、可轮换。
- ACME 只做出站：面板访问 CA 与 DNS provider API，**不开放 80/443 入站**。DNS-01 失败
  会清理自己写的 TXT；只有 provider 拒绝删除时才需要去控制台手工清理。
- 多主域名/SNI：`registry.json` 的 `active` 是**每个主域名各一张**，不再有「PKCS#12
  静默优先」。迁移后旧文件保留，但不再参与选择；实际生效的证书以注册表为准。
- staging 证书不被浏览器信任，不要设为默认；默认策略会阻止自动切换，手动切换二次确认。
  锁死时用局域网地址切回可信证书，或停容器改 `certs/registry.json` 的 `active`。
- 证书上传/签发/切换要求 HTTPS + 开发者提权；写 DNS 凭据还要面板密码二次确认；裸 HTTP
  下这些接口返回 `tls_required`。

## 3. 面板不管的事

- **网络边界**：它不替你选"要不要暴露到公网"。反代鉴权、IP 白名单、VPN 都得你自己配。
- **宿主权限**：容器里它是 root，仅此而已；宿主上发生了什么它不知道也管不了。
- **agent 本身的可信度**：agent 会执行模型让它执行的任何东西。你再信任模型，也不该把
  生产 key 和它放一个笼子里。
- **资源的滥用**：除了 MC 的内存上限，没有 CPU/磁盘配额。
- **第三方工具自身的能力与门禁**：品牌工具自带的终端/命令执行（PI WEB 的浏览器终端、
  ZCode 的网页终端，以及以后任何带终端的品牌 UI）属于上游产品形态。面板负责安装、起停与
  反代，不替它加门；它的鉴权由该工具自己决定。

## 4. 错误的部署方式（自查清单）

| 你可能这么干 | 为什么会出事 | 正确做法 |
|---|---|---|
| 裸 HTTP 直接暴露公网 | 口令、Cookie、屏幕内容全是明文；开发者密码只能当第二道验证，Web Shell/终端仍不可用 | 反代终结 TLS，或在面板里启 HTTPS |
| `auth.disabled: true` + 绑 `0.0.0.0` | 代码会拒绝这个组合；如果你绕过了，等于把整台面板送人 | 免登录只在回环上开 |
| 把 `/var/run/docker.sock` 挂进容器 | 面板被攻破 = **宿主 root**，前面所有隔离全部作废 | 不要挂 |
| 裸部署用 root 起面板 | 面板派生的每个 agent 也是 root，它能改一切 | 用 systemd `User=hdsl` + §10.0 的沙箱 |
| 容器加 `--user 1000` 覆盖 | 面板自己就是 1000，降权失效，秘密回到"同 uid 可写" | 要隔离就别覆盖用户 |
| 把 `/data` 放在共享盘/网盘 | 权限语义不可控（服务端能 chown 成任何人），性能和锁也糟；MC 存档尤其 | 本地盘 + 定期备份 |
| 给不受信的人开实例 | **实例之间没有隔离**（同 uid 1000，实例目录组可写），一个 agent 能改另一个的代码 | 一人一个容器，或别开 |
| 在容器里装 `sudo` / 给 agent root | 等于把宿主交出去；`docker exec -u 0` 才是维修窗口 | 不给 sudo |
| 把面板当公网 SaaS | 没有多租户、没有配额、没有独立的速率限制 | 自用或小团队内网 |

两件会让人意外的**副作用**（不是漏洞，但值得知道）：

- **bind mount 的宿主目录会被校正属主**：容器入口每次启动把 `/data`、`/home/hdsl`（含
  `workspace`、`mc` 两个挂载点）chown 到 uid 1000。所以别把"你不想被改属主的共享目录"挂进来。
- **手动 `docker volume create` 出来的空卷是 root 的**：Docker 只在"卷为空且挂在镜像里存在的
  目录上"时用镜像里的属主播种，预先建好的空卷没有这一步。首次启动会被入口校正，属于正常。

## 5. 出事之后

1. **先别重启**（内存里的会话、提权、E-Stop 状态一重启就没了）。能登录就先按 E-Stop。
2. **看审计**：`<data>/logs/audit-*.jsonl`，按时间、来源地址、动作过滤。
3. **假设这些都已泄漏，全部换掉**：供应商 API key、面板口令、开发者口令、TLS 证书与私钥、
   各 agent 自己的凭据（kimi / opencode / claude-web 在各自实例 home 里）。
4. **取证**：容器不要 `docker rm`，先 `docker export` 一份；日志目录 `cp` 走。
5. **恢复**：换一台干净机器、用已知干净的镜像、新的 key，再考虑把数据导回去（只导存档，
   不导 `dsh/` 与 `brands/` 里的代码）。

## 6. 已知缺陷与取舍（诚实清单）

- **出站 TLS 的一次性授权窗口，到期不会自己收紧**（要重启容器或再操作一次才生效）。
  已知，未修——所以授权时请给短时长，用完主动撤销。
- **供应商 API key 对 agent 可读**：它在 `<用户目录>/launcher-settings.json` 的 `accounts` 段，
  属主是 uid 1000。agent 与 ACP 会话要用它调模型，锁上会把功能弄坏。按"一台机器一套 key、
  额度按机器给、能撤销能轮换"来用。
- **实例之间互相可写**（同 uid 1000）。
- **Windows 没有 POSIX 0600 语义**：凭据文件可能被同机其他账户读到，按单用户机器对待。
- **IE11 / 老浏览器 + 裸 HTTP：已知、接受、不打算补的明文洞。** 这不是等修的 bug；
  完整的时间线、实际暴露面和「如果非要这么干」的清单见 §6.1。
- **HTTP 下的密码/聊天加密只防被动嗅探。** 登录/改密/开发者提权的密码字段，以及
  `/api/chat/*` JSON 和 `chat:*` WebSocket 帧，会由 X25519 + HKDF + ChaCha20-Poly1305
  包裹；它不防主动 MITM、不防 JS 被替换、也不防首次公钥被替换。支持 ES2020 的浏览器
  会用这层；旧浏览器/curl 仍可发明文（服务端为兼容而接受）。要真正的传输安全，
  仍然必须用 HTTPS 或 SSH 隧道。
- **反代后的"本机"判定由 `network.trusted_proxies` 决定，默认不配置 = 不信任何转发头。**
  面板挂在同机 nginx/Caddy 后面时，所有外部请求的 `remoteAddr` 都是 `127.0.0.1`：
  agent 的 loopback 限制与"远程需要面板会话"会一起失效、开发者守卫的明文升级不触发、
  登录节流变成全站共享预算（外部打满后可以锁死所有人登录）。配上
  `network.trusted_proxies` 之后，这些判定才按 `X-Forwarded-For` 解析出的真实客户端执行。
  **只在面板确实只经这些反代暴露时配置**；直连暴露时配上它，等于允许客户端自己填写
  来源地址来绕过上述全部限制。还有两个部署硬要求：反代必须 **append 或 overwrite**
  `X-Forwarded-For`（缺失时按连接对端算，同机反代下就是本机）；转发项必须是 IP 字面量，
  畸形的转发项一律按外部来源处理，不会回本机放行。`trusted_proxies` 条目在加载时校验并
  规范化（`0:0:0:0:0:0:0:1` 与 `::1` 等价），非法条目直接拒绝启动。
- **没有独立的 CSRF token**：靠 `SameSite=Strict` + 写接口只收 JSON 请求体两层。够用，但不是
  硬保证。
- **实例 token 在 URL 里**（`/i/<id>/?token=…`）：会出现在浏览器历史、某些反代访问日志里；
  它每进程随机、重启即换，别把它当长期凭据。
- **品牌自带的终端不受面板终端五门约束**：PI WEB 的浏览器终端、ZCode 的网页终端
  （上游 3.14.3 起就有），运行身份与 agent 相同，只有各自实例的访问密码。要与面板终端
  同等门禁，只能不部署它、把 `developer_guard.scope` 设为 `proxy`，或把实例隔离到独立
  uid / 容器。

### 6.1 反面教材：IE11 + 裸 HTTP + `/plain`

先把结论说死：**这三样东西放在一起，没有任何传输安全。** 这不是一个等修的 bug，
而是一个明确接受、并且应该被反复鞭尸的取舍——保留它是因为兼容性，不是因为安全。

**为什么会有这条路**

- `/plain` 是给 w3m / lynx / IE11 / 关 JS 的旧机器用的无 JS 表面；它没有脚本，
  自然也用不了 081b 那套密码/聊天信封。
- 为了 curl 和旧客户端不炸，服务端继续接受明文密码；聊天也继续接受明文 JSON / WS。
- 11267 之后，远程裸 HTTP 在**已有开发者密码**时强制 `developer_guard=ALL`，`/i`、`/plain`
  不再硬 403，改为「第二因子 + 警告」；还没设密码时保留配置的档位（默认 `off`），
  否则首次部署会被自己的守卫锁死。这降低了「点开就能操作」的风险，但**没有把明文变成密文**。

**裸 HTTP + `/plain` 实际暴露什么**

| 数据 | 状态 |
|---|---|
| `/plain/login` 的 username / password | 明文 POST |
| 登录后的 `hdsl_session` Cookie | 明文 Bearer（HTTP 下没有 `Secure`） |
| `/plain` 的会话列表、聊天正文、发送内容、附件 | 明文 |
| `/plain/elevate` 的开发者密码 | 明文 POST |
| SPA 的 HTML / JS、普通 API 响应、`/i/<id>/` 反代内容 | 明文 |
| SPA 的密码字段、`/api/chat/*` JSON、`chat:*` WS 帧 | 有信封，但只防被动嗅探 |
| IE11 / `/plain` 上的密码与聊天 | **没有信封可用** |

被动嗅探者拿到 Cookie 就能重放；远程 HTTP 的 `developer_guard=ALL` 会把大部分 API 再
挡一道，但 Cookie 本身仍是明文 Bearer，不是加密。主动 MITM 可以替换 JS 或公钥，让
信封失效。「HTTP 加密」在这条路上不是救命稻草——它只覆盖现代浏览器的一小块表面。

**如果非要这么干，最低限度**

1. 不要把端口映射到公网；只放在 loopback、SSH 隧道、WireGuard / Tailscale 后面。
2. 能在前面终结 TLS 就终结 TLS；IE11 在 Win7 上要手动启用 TLS 1.2，别拿「老」当借口。
3. 反代直接 403 掉 `/plain` 与 `/plain/*`（不需要旧浏览器时）；需要时至少加 HTTPS 或 IP 白名单。
4. 这种部署上不要放生产 key、团队共用账号或高价值凭据；按「已经泄漏」准备轮换。
5. 一旦在不可信链路上开过裸 HTTP，当作已入侵处理：翻审计、换口令、换 key、看 `/data`。

**收口方向（如果以后要补）**

最直接的是让 `/plain` 在「非 TLS 且非回环」时重新 403（081b 曾经这样做，11267 为了
HTTP 第二因子取消了）；或者给它一个默认关闭的 `plain.allow_cleartext` 开关，让部署者
显式承认风险。**产品上保留旧浏览器支持没问题，但安全文档不能把它说成安全。**

### 6.2 Java4Shell（CVE-2026-114938）

OpenJDK 的 AVX-512 VBMI Base64 解码 intrinsic 在特定畸形输入上会越界写堆内存。影响
HotSpot 17.0.6+、21、25、27，且**只在 x86-64 且 CPU 暴露 `avx512_vbmi`**（Ice Lake /
Sapphire Rapids、AMD Zen 4/5）时命中；ARM、老 Xeon、AMD Zen 4 以前的机器不在这条路径上。
CVSS 3.1 为 8.1，公开触发串存在，截至 2026-11-18 没有公开的在野利用报告。

面板自己的登录密码信封在**认证之前**就会 `Base64.getUrlDecoder().decode()` 解
`clientPublicKey`/`nonce`/`ciphertext`；在受影响的 JDK + CPU 上，未认证请求可以进入这条
路径。登录限流发生在解码之后，不能阻止解码本身。缓解顺序：

1. 升级到 OpenJDK `21.0.13.1+`（17/25/27 对应 `.1` 构建）；
2. 暂时升级不了时：容器入口在 x86-64 上自动加 `-XX:-UseBASE64Intrinsics`，直接移除
   受影响的 intrinsic，不依赖 CPU flags；`HDSL_JAVA4SHELL_GUARD=0` 可关闭。裸 jar
   需要自己加 `-XX:-UseBASE64Intrinsics`（Java 9+）或换已修复的 JDK；
3. 检查：运行中的容器 `jcmd 1 VM.flags | grep UseBASE64` 应包含
   `-XX:-UseBASE64Intrinsics`；裸 jar 再用 `lscpu | grep -o avx512_vbmi` 判断是否在
   攻击面上。

不要在生产面板上直接试公开 PoC；要验证就用临时数据目录、临时端口起一个实例。升级 JDK
并确认补丁生效后，可以去掉 `-XX:-UseBASE64Intrinsics`（它会关闭硬件加速的 Base64
解码；修复后的 JDK 不再需要）。
