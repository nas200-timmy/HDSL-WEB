# 安全说明

> 这一页写给**要把它暴露到网络上、或者让它跑别人的 agent 的人**。
> 一句话：**面板的作用是把 agent 关进你选的笼子里；它不负责把笼子造好。**

其它文档各讲一面：`design-notes.md §7` 记「为什么这样设计」，`web-shell.md §4` 是终端那条
攻击面，`deployment.md` 讲怎么装。这一页只讲三件事：**你可能被谁害、面板挡住了什么、
你自己怎么把它搞砸。**

---

## 0. 先花一分钟回答三个问题

1. **谁可能碰到这个端口？** 公网扫描器 / 同内网的其他人 / 只有你自己。
2. **谁可能在面板里跑代码？** 你自己 / 你信任的同事 / 不受信的 agent 与用户提供的文件。
3. **这台机器上还有什么值钱的东西？** 别人的数据、生产环境的 key、内网里能横向访问的服务。

这三个答案决定后面每一条的权重。**答不出第 3 题的人，通常会把它配成公网可访问的样子。**

---

## 1. 威胁：按可能性排

| 威胁 | 谁 | 面板能挡吗 | 你要做什么 |
|---|---|---|---|
| 公网扫描、撞库 | 互联网上的任何人 | **能挡大半**：登录门 + 失败预算 + HTTPS | 别裸 HTTP 暴露；前面加反代/VPN/白名单 |
| 被投毒的 agent | 模型自己、它拉下来的包、`curl \| sh`、提示注入 | **挡一部分**：容器里 agent 降权、秘密文件 0700 | 别把生产 key 配进来；容器部署 |
| 同一台机器上的其他账户 | 多用户主机、裸部署 | **挡不住**：0600 只在有 uid 分离时才有意义 | 裸部署按单用户机器对待 |
| 会话 Cookie 被偷 | 共享设备、XSS、日志泄漏 | **挡得住一部分**：HttpOnly + SameSite + HTTPS + 提权 | 别在不可信设备登录 |
| 面板自身的漏洞 | 任何人 | **挡不住**：面板被攻破 = 它能做的事全丢 | 只信你审过的版本；最小暴露 |
| 宿主管理员 / 容器逃逸 | 有宿主权限的人 | **挡不住**，这是上限 | 宿主本身要可信 |
| 你自己的误操作 | 你 | **挡一部分**：备份、E-Stop、审计 | 先备份再点 |

**这张表的读法**：面板把自己的边界守得挺紧，但边界之外的东西（网络、宿主、agent 的可信度、
key 的价值）全是部署者的责任。

## 2. 面板实际做了什么（可以逐条核对）

### 2.1 进门这一层

- **口令存储**：PBKDF2WithHmacSHA256，per-user 盐，21 万次迭代；文件原子写入并收紧到 0600。
- **失败预算**：同一来源地址 5 分钟内错 15 次，第 16 次起拒绝 10 分钟（响应带 `Retry-After`），
  期间**口令正确也进不来**；一次成功清零。拒绝发生在**核对口令之前**——核对本身
  （21 万次 PBKDF2）就是攻击者想让你付的那笔开销。
- **来源地址取 TCP 对端**，不信 `X-Forwarded-For`。所以面板架在反代后面时，这个预算是
  **所有访问者共用**的（这是有意的：伪造头部换 IP 成本太低）。
- **会话**：默认 168 小时（`sessionTtlHours`），Cookie 是 `HttpOnly` + `SameSite=Strict`，
  HTTPS 下加 `Secure`。改密码或改用户名会立刻踢掉该用户的其它会话。
- **`auth.disabled: true` 只在绑定回环地址时允许**——免登录可以，误配到公网不行。

### 2.2 第二把锁：开发者模式

它守的是"能执行代码"那一类动作：实例终端、E-Stop、开发者守卫档位、装包等。

- **只在真 HTTPS 下可用**（看的是当前连接器是否真的在讲 TLS，或受信反代发来的
  `X-Forwarded-Proto: https`）；裸 HTTP 下开发者模式整体不可用，终端按钮隐藏、接口 403。
- **口令存在独立的 `auth/developer.json`（0600）**，与登录口令分开：偷到登录态不等于能开终端。
- **提权是会话级的**：默认 30 分钟滑动（`DeveloperElevation.TTL`，可一次延长到 3 小时）；
  10 分钟内错 3 次，这个「会话 + 地址」就被锁 10 分钟。
- 提权的 key 绑定「会话 + 来源地址」，换一个地址不算提权。

### 2.3 实例终端（效果上等于 RCE，所以门最多）

- 顺序固定：**E-Stop → Web Shell 总开关 → HTTPS → 开发者口令已设置 → 已提权**，五道全过才谈启动。
- 启动的是**适配器解析出来的 argv**，不经 shell：Windows 上 `.cmd` / `.bat` / `.ps1` / `.com`
  一律拒绝（`CreateProcess` 会悄悄把它们交给 `cmd.exe`，那等于塞回一个 shell）。
- 一个实例同时只有一个终端；重连发新 ticket 而不是重启 agent；关浏览器只是 detach。
- ticket 是一次性的：32 字节随机、30 秒过期、绑定「会话 + 实例」。
- 容器里面板是 root、终端进程降权到 uid 1000（见 §2.7）。

### 2.4 反代与实例网页

- `/i/<id>/` 要会话；实例的访问 token 每进程随机、只存内存、重启即换。
- 反代只转发面板算出来的目标，请求里没有"我要连哪个端口"这种参数。

### 2.5 紧急停机（E-Stop）

- 三次确认，第二次要手打「紧急停机」四个字；按下后先关所有终端，再杀所有实例的进程树，
  审计里记一笔。**不跑用户的 post-exit 脚本**——紧急停机不该再去执行用户代码。
- 状态只存在内存里：**重启面板或容器就解除**，这是唯一的物理恢复方式；冷却 1 小时内谁都不能解除。

### 2.6 审计

- 记谁、从哪个地址、做了什么（登录、终端开关、实例起停、装包、E-Stop、证书授权与撤销…），
  不记屏幕内容、不记 key。
- 文件 `<data>/logs/audit-*.jsonl`，0600；**保底保留 180 天**（低于这个数就答不上"上季度谁删了那个世界"）。

### 2.7 容器里的身份划分（v0.6.43 起）

- **面板是 root**，`auth/`（含开发者口令哈希）、`certs/`（TLS 私钥）、`logs/`（审计）、
  `server.yaml` 是 root `0700/0600`；
- **每个 agent 进程降权到 uid 1000**（`setpriv`，exec 原地替换，进程组与 PTY 会话不变）；
- 所以 agent **读不到也改不了**面板的凭据，也 `kill` 不掉面板、ptrace 不了它；
- **裸部署没有这一层**：面板与 agent 同一个 uid，那些 0600 文件对 agent 是可读可写的。
  要隔离请用容器部署。

## 3. 面板不管的事

- **网络边界**：它不替你选"要不要暴露到公网"。反代鉴权、IP 白名单、VPN 都得你自己配。
- **宿主权限**：容器里它是 root，仅此而已；宿主上发生了什么它不知道也管不了。
- **agent 本身的可信度**：agent 会执行模型让它执行的任何东西。你再信任模型，也不该把
  生产 key 和它放一个笼子里。
- **资源的滥用**：除了 MC 的内存上限，没有 CPU/磁盘配额。

## 4. 错误的部署方式（自查清单）

| 你可能这么干 | 为什么会出事 | 正确做法 |
|---|---|---|
| 裸 HTTP 直接暴露公网 | 口令、Cookie、屏幕内容全是明文；而且开发者模式在裸 HTTP 下整体关闭，你会开始怀念终端 | 反代终结 TLS，或在面板里启 HTTPS |
| `auth.disabled: true` + 绑 `0.0.0.0` | 代码会拒绝这个组合；如果你绕过了，等于把整台面板送人 | 免登录只在回环上开 |
| 把 `/var/run/docker.sock` 挂进容器 | 面板被攻破 = **宿主 root**，前面所有隔离全部作废 | 不要挂 |
| 裸部署用 root 起面板 | 面板派生的每个 agent 也是 root，它能改一切 | 用 systemd `User=hdsl` + §10.0 的沙箱 |
| 容器加 `--user 1000` 覆盖 | 面板自己就是 1000，降权失效，秘密回到"同 uid 可写" | 要隔离就别覆盖用户 |
| 把 `/data` 放在共享盘/网盘 | 权限语义不可控（服务端能 chown 成任何人），性能和锁也糟；MC 存档尤其 | 本地盘 + 定期备份 |
| 给不受信的人开实例 | **实例之间没有隔离**（同 uid 1000，实例目录组可写），一个 agent 能改另一个的代码 | 一人一个容器，或别开 |
| 在容器里装 `sudo` / 给 agent root | 等于把宿主交出去；`docker exec -u 0` 才是维修窗口 | 不给 sudo |
| 把面板当公网 SaaS | 没有多租户、没有配额、没有独立的速率限制 | 自用或小团队内网 |

两件会让人意外的**副作用**（不是漏洞，但值得知道）：

- **bind mount 的宿主目录会被校正属主**：容器入口每次启动把 `/data`、`/home/hdsl`（含
  `workspace`、`mc` 两个挂载点）chown 到 uid 1000。所以别把"你不想被改属主的共享目录"挂进来。
- **手动 `docker volume create` 出来的空卷是 root 的**：Docker 只在"卷为空且挂在镜像里存在的
  目录上"时用镜像里的属主播种，预先建好的空卷没有这一步。首次启动会被入口校正，属于正常。

## 5. 出事之后

1. **先别重启**（内存里的会话、提权、E-Stop 状态一重启就没了）。能登录就先按 E-Stop。
2. **看审计**：`<data>/logs/audit-*.jsonl`，按时间、来源地址、动作过滤。
3. **假设这些都已泄漏，全部换掉**：供应商 API key、面板口令、开发者口令、TLS 证书与私钥、
   各 agent 自己的凭据（kimi / opencode / claude-web 在各自实例 home 里）。
4. **取证**：容器不要 `docker rm`，先 `docker export` 一份；日志目录 `cp` 走。
5. **恢复**：换一台干净机器、用已知干净的镜像、新的 key，再考虑把数据导回去（只导存档，
   不导 `dsh/` 与 `brands/` 里的代码）。

## 6. 已知缺陷与取舍（诚实清单）

- **出站 TLS 的一次性授权窗口，到期不会自己收紧**（要重启容器或再操作一次才生效）。
  已知，未修——所以授权时请给短时长，用完主动撤销。
- **供应商 API key 对 agent 可读**：它在 `<用户目录>/launcher-settings.json` 的 `accounts` 段，
  属主是 uid 1000。agent 与 ACP 会话要用它调模型，锁上会把功能弄坏。按"一台机器一套 key、
  额度按机器给、能撤销能轮换"来用。
- **实例之间互相可写**（同 uid 1000）。
- **Windows 没有 POSIX 0600 语义**：凭据文件可能被同机其他账户读到，按单用户机器对待。
- **没有独立的 CSRF token**：靠 `SameSite=Strict` + 写接口只收 JSON 请求体两层。够用，但不是
  硬保证。
- **实例 token 在 URL 里**（`/i/<id>/?token=…`）：会出现在浏览器历史、某些反代访问日志里；
  它每进程随机、重启即换，别把它当长期凭据。
