# 种子地图内核：实测精度与已知差异

> 这份文件记录"内核算出来的"与"游戏真实生成的"差在哪里、差多少、为什么。
> 它是 [seedmap.md](seedmap.md) 的精度附件，不是待办列表——目前接受这些差异。

## 怎么测的

固定的种子 `-8042010651245935275`，每个版本起一次**真服务端**，让它生成
`±2 区块`（约 80×80 格）的完整区域，然后把服务端写进区块文件的群系，与内核
算出的群系**逐格对比**：

- 对比单位是 4×4 格（区块里的群系单元），每个版本约 8500～14000 个单元；
- 地表高度取自区块自己的高度图，内核按**该格的地表高度**查询，不用固定 y；
- 服务端数据不经过内核，直接读区域文件，避免"自己跟自己比"。

## 结果

| 版本 | 吻合 / 总数 | 差异率 | 差异构成 |
|---|---|---|---|
| 1.12.2 | 7818 / 10048 | 22.2% | `taiga→taiga_hills` 999、`forest→wooded_hills` 811，其余零散 |
| 1.14.4 | 6346 / 8464 | 25.0% | `forest→wooded_hills` 1813、`forest↔river` 226 |
| 1.16.5 | 6606 / 8464 | 22.0% | `forest→wooded_hills` **1858，仅此一种** |
| 1.21.4 | 4349 / 14304 | 30.4%（见下） | `plains→dripstone_caves` 8239 为主 |

> 1.21.4 早先按固定 y=63 比过一次，差异 69.6%；改用每格真实地表高度后降到 30.4%，
> 但"地表返回洞穴群系"的问题仍在。

## 解释

**一、旧版（1.12 – 1.16）的误差基本都是"丘陵变体"**

内核在游戏给出母群系的地方，约两成情况下给出对应的丘陵变体。1.16.5 是最干净的
样本：1858 条差异没有一条是别的类型。

这一层与 cubiomes 的 C 版**逐格一致**（见下），所以不是移植错误，而是上游实现对
这几个版本的丘陵判定与游戏存在系统性偏差。目前选择接受。

对"看个大概"影响很小——森林丘陵和森林在地图上都属于绿色系；对"按坐标找特定
群系"有影响，用户可能被带到丘陵而不是平原。

**二、新版（1.18+）的误差是另一类：地表位置返回了洞穴群系**

`plains → dripstone_caves` 占 1.21.4 差异的绝大部分。判断是内核在地表取样时取了
略低于地表的高度，落进了洞穴的群系层。修复方向是把取样点上移到地表之上，
但尚未动工。

## 与 cubiomes（C 版）的一致性

同一批坐标喂给 C 版查询工具，与 Java 内核**逐格比对 8464 格，0 差异**；
把 L1 采样从 900 个孤立点扩到 18432 个点（8×8 连续区块），仍然 0 差异。

结论：**移植是忠实的。差异来自上游实现与游戏之间，不来自移植。**

## 当前定位

| 用途 | 建议 |
|---|---|
| 看大陆、海洋、气候分布 | 可以直接用 Java 模式 |
| 按坐标找某个具体群系 | 用服务端模式，或接受约两成的误判 |
| 结构坐标 | 与群系误差不是同一条路径，另行验证 |

界面上 Java 模式标注为"近似"，服务端模式标注为"精确"。
