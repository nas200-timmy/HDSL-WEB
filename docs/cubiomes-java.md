# 种子地图内核（生物群系 / 结构的纯计算实现）设计稿

> 一句话：把"给定种子、给定坐标，这里是什么群系、附近有什么结构"变成纯 Java 计算，
> 不再依赖启动 Minecraft 服务端。
>
> 状态：**设计稿，未开工**。写这份文档的目的是交接——无论接手的是人还是 agent，
> 读完后应该能直接开工，并且知道什么算做完。

## 0. 先读这一节（交接说明）

**这份文档不包含任何部署信息。** 没有真实域名、没有主机路径、没有凭据。文中出现的
`<数据目录>`、`<版本目录>` 都是占位符，实际值由部署者决定。接手时也不要把这些
信息补进来——这份文档可能被单独拿出去给别人看。

**这个内核要能独立编译运行。** 把它从仓库里拷出来，`javac` + 一个 `main`
就能出结果；同时它也是面板的一个普通依赖，嵌回去不需要任何特殊初始化（见 §5）。
判据只有一条：**不 import 面板的任何类，不依赖 Web 框架、配置系统、数据库或
日志实现。** 许可证不参与这条判断——它跟随面板（见 §7）。

**建议的阅读顺序**：§1 背景 → §2 现状 → §5 独立性 → §6 结构 → §8 验证。
前三节决定"为什么"，后三节决定"怎么写、怎么证明写对了"。

## 1. 面板是什么

一个自托管的 Web 面板，用浏览器管理两类东西：

- **AI agent 实例**：在容器里跑编码助手，通过网页交互；
- **Minecraft 服务端实例**：安装、启停、看控制台、改配置、管世界和玩家。

面板本身是单用户的：一个操作者，一套密码，所有实例都在同一台机器（通常是家用
NAS 或一台小服务器）上。它不提供多租户，也不做云托管。

## 2. 种子预览现在是什么

"种子预览"是面板里的一个功能页：输入版本 + 种子，得到一张地图，用来看这个世界
值不值得开。

**当前实现（服务端路线）**

1. 从面板缓存里取该版本的官方服务端程序（没有就下载一次，校验哈希）；
2. 在临时目录里起一个一次性服务端，生成一块方形区域；
3. 停服，读它写出的区块文件，解析出生物群系、地表方块、结构起点；
4. 画成 PNG，缓存图片与元数据；临时世界删除。

**已经具备的**

- 独立页面（不依附任何一台服务器实例），版本可选，没下载过的版本现场拉取；
- 两种渲染：详细地图（地表材料 + 明暗）、群系速览（纯群系色块）；
- 最近 30 个结果落盘缓存，可查看、可删除，重启不丢；
- 结构化输出：图片、`meta.json`、以及给 agent 读的纯文本报告；
- 缩放、平移、选点、坐标读数、自适应网格与比例尺。

**已经量出来的问题**

| 数据 | 值 |
|---|---|
| 单区块生成（老版本） | 15–20 ms |
| 单区块生成（最新版本） | ~0.9 s |
| 1024×1024 格（4096 区块） | 1.5 分钟 ～ 跑不完 |
| 8192×8192 格（65536 区块） | 20 分钟以上 |

结论：**"跑真服务端"这条路的上限就在这里**。它能给出绝对可信的结果，但不可能
做到"拖到哪看到哪"。这就是本项目的由来。

## 3. 为什么要换内核

地图软件（包括几个成熟的网页种子地图）之所以能瞬间铺开几万格，是因为它们**不生成
世界**：只计算生物群系归属和结构落点。这类实现里最成熟的一个是 cubiomes（MIT），
纯 C，无依赖。

同一块 8192×8192 的区域：

| 方式 | 耗时 |
|---|---|
| 真服务端 | 20 分钟以上 |
| cubiomes（C） | ≈ 0.5 秒 |
| 本设计（Java 复刻） | ≈ 1–2 秒 |

差距不来自语言。JIT 之后的 Java 跑这种浮点噪声循环通常只比 C 慢 1–3 倍；差别在于
一边在生成整个世界，另一边只算几个噪声函数。

## 4. 目标与非目标

**目标**

- 主世界生物群系查询：任意坐标、任意种子、多个版本；
- 结构位置：村庄、神殿、女巫小屋、林地府邸、海底神殿、海底废墟、沉船、废弃传送门、
  掠夺者前哨、远古城市、试炼密室、要塞、矿井；
- 史莱姆区块（已有公式）、出生点、要塞同心环；
- 版本范围：**1.12.2 ～ 最新正式版**。1.12.2 是兼容下限，比它更早的版本不做。

  按族分两套实现，分界在 1.18（地形生成从"层栈"换成 multi-noise）：

  | 版本 | 族 | 优先级 |
  |---|---|---|
  | 最新正式版（写作时为 26.x 线） | 新版本线 | 先用 L2 确认与 1.21 是否同一套气候系统，再决定 |
  | 1.21.x | multi-noise | 首要 |
  | 1.20.x / 1.18.x | multi-noise | 次要（同一套系统，参数表不同） |
  | 1.16.x | 旧层栈，3D 群系 | 首要 |
  | 1.14.x | 旧层栈，2D 群系 | 首要 |
  | 1.12.2 | 旧层栈 | **兼容下限**，最后做 |

  下限写死是有意的：比 1.12.2 更早的版本参数表更旧、用户更少，为它们维护一套
  表不划算。不接受"顺手支持一下 1.11"这类补丁。

**非目标（v1）**

- 地形高度、方块、光照——那是渲染问题，继续由"跑真服务端"的详细地图负责；
- 下界与末地（v1 只做主世界）；
- 自定义维度、数据包、模组；
- 任何形式的服务器端进程管理。

**永远不做**

- 从反编译的游戏源码复制代码进实现。见 §7。

## 5. 独立性要求（重要）

这里的"独立"只指一件事：**不依赖面板也能编译、能跑**——把 `core/` 目录连同它的
测试一起拷走，`javac` + 一个 `main` 就能出结果。它当然也照常作为普通依赖嵌回面板，
那才是它的主要用法。

不是"另起一个项目"、也不涉及许可证（见 §7，跟随面板）。约束：

1. **零依赖**：只用 JDK 标准库。不引用 Web 框架、JSON 库、日志框架、配置类。
   需要输出结构化数据时返回普通 record，由调用方决定怎么序列化。
2. **无状态**：核心对象不可变或只读；不持有全局单例、不读环境变量、不读文件系统
   之外的配置。
3. **不依赖面板的包**：`core` 包里不允许出现 `import` 指向面板代码。
4. **入口小而稳定**：对外只暴露一个门面（见 §6），其余全是 `package-private`。
5. **可测**：所有核心入口都能在纯 JVM 里跑，不需要起服务器、不需要网络。
6. **两种用法都要成立**：独立运行时没有"必须由面板提供的初始化"；嵌回面板时
   也不需要为它开特例（不要求面板改启动顺序、不要求单例注入）。

"独立"不等于"重复造轮子"：面板需要的适配（读配置、写缓存、走 HTTP）放在
**另一个包**里，它依赖 core，core 不依赖它。

## 6. 结构

```
core/                              ← 可独立使用的部分（零依赖、可单测）
  Noise.java            噪声：Perlin、八度叠加、位置随机
  BiomeNoise.java       气候参数、multi-noise 查表、旧版层栈
  BiomeTables.java      每个版本的群系参数表（生成，不手抄）
  Generator.java        层栈生成器、结构放置（间距/分离/盐）
  Finder.java           结构定位（由近及远找最近的落点）
  SeedMap.java          门面：biomeAt / structures / spawn / strongholds
  Version.java          版本分支枚举与解析（LEGACY / MODERN）
  package-info.java     许可证与来源说明

adapter/                           ← 面板适配（允许依赖面板）
  SeedMapBackend.java   把 core 的结果翻成面板的图片/JSON/文本
  ServerBackend.java    现有实现（跑真服务端），保留为对照与详细地图
```

`SeedMap.java` 的对外形状（示意，不是最终签名）：

```java
Biome biomeAt(Version version, long seed, int blockX, int blockZ);
List<Structure> structures(Version version, long seed, int x0, int z0, int x1, int z1);
BlockPos spawn(Version version, long seed);
List<BlockPos> strongholds(Version version, long seed);
```

返回类型用 record + 枚举，不用字符串；版本用显式枚举，不做字符串解析的隐式行为。

**面板侧**只做三件事：参数校验、把 core 的结果渲染成图片/文本、写缓存。
任何"这个群系叫什么颜色"之类的判断属于适配层，不属于 core。

## 7. 来源与许可

**许可证跟随面板（GPL）。** 这个仓库整体按 GPL 分发，`core` 不另设许可证，
接手的人不需要为它单独考虑授权问题。

算法实现移植自 MIT 的 cubiomes。MIT 只要求保留版权声明，与 GPL 兼容，所以在
移植出来的文件头保留它的出处与版权行即可，不改变仓库整体的授权。

**进 `core` 的代码只能来自它。** 反编译的 Minecraft 源码（由使用者自备，不入库）
只用于两件事：

1. 回答"这个常数为什么是这个值"；
2. 构造 §8 的 L2 验证器（调用游戏自带的群系源），**只读，不复制**。

它自身的许可证禁止发布派生源码，所以既不能进实现，也不能进发布物。

## 8. 三层验证

这是本设计能成立的前提。三层缺一不可。

| 层 | 对比对象 | 规模 | 判定 | 目的 |
|---|---|---|---|---|
| **L1** | Java 版 ↔ cubiomes C 版 | 百万级采样点 | **完全一致** | 抓移植错误，全自动，几十秒跑完 |
| **L2** | Java 版 ↔ 游戏自带群系源 | 每版本几十个种子，边界密集 | 一致，或登记为已知偏差 | 抓 cubiomes 与该版本的偏差 |
| **L3** | Java 版 ↔ 真服务端生成的区块 | 几十个种子，整块区域 | 一致 | 端到端回归，覆盖结构与渲染链路 |

**L1**：把 cubiomes 编成一个只做查询的小程序（只在测试环境用，不进发布物），
随机种子 × 随机坐标比对。重点是**边界密集采样**：先找出群系边界，再在边界 ±8 格
内取点——绝大多数移植错误出在区间端点的开闭。

**L2**：写测试工具，启动游戏自带的注册表与群系源，直接问任意坐标，不生成区块。
差异出现时，去读对应版本的实现确认谁对。差异若无法消除，登记进
`docs/seedmap-deviations.md`，该版本标记为"实验性"。

**L3**：复用现有的服务端后端生成一块区域，逐格比对。慢，但它是唯一的
"跑在真实游戏里"的证据。

**验收门槛**：L1 差异 = 0；L2 差异 = 0 或全部登记；L3 差异 = 0。
任何一层不过，该版本不得默认启用新内核。

## 9. 性能目标

| 场景 | 目标 |
|---|---|
| 单点 `biomeAt` | < 5 µs |
| 1024×1024 格 @ 4 格/点 | < 1 秒 |
| 8192×8192 格 @ 16 格/点 | < 3 秒 |
| 单类型结构查询（半径 2048） | < 100 ms |

实现纪律：噪声循环内不分配对象；群系用 `short` 索引而不是字符串；结果按
256×256 格的瓦片缓存。

## 10. 交付物与验收

一个交接完成的标志：

- [ ] `core/` 能在没有任何面板代码的 classpath 下编译；
- [ ] `core/` 有独立的单元测试，`mvn/gradle` 一条命令跑完；
- [ ] L1 验证脚本可重复运行，输出差异数为 0；
- [ ] L2 验证脚本至少覆盖一个版本，差异已登记；
- [ ] README 说明如何把 `core/` 拿出来独立编译运行（含一个 20 行以内的小例子），
      并说明它同时作为普通依赖嵌回面板；
- [ ] 面板接入后，"群系速览"不再启动服务端进程。

## 12. 风险

| 风险 | 应对 |
|---|---|
| 参数表抄错 | 用生成器产出，禁止手抄；L1 卡住 |
| 现代版本 multi-noise 复杂 | 先只做群系，结构后置；一次只加一个版本 |
| 上游实现对某个小版本本身不准 | L2 发现 → 登记 → 该版本回退旧后端 |
| 版本矩阵失控 | 一次只支持一个版本，三层全过才发布 |
| 许可 | 跟随仓库的 GPL；只从 MIT 来源移植算法，保留其版权声明；反编译源码只读 |
| 被单独抽取后无人维护 | `core/` 自带 README 与独立测试，脱离面板也能跑 |
